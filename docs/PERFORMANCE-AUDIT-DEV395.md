# Development Version 395 performance audit

## Evidence reviewed

The supplied Development Version 394 sessions contained 3,908 and 9,832 BGL log entries. The larger session included 5,251 `RenderDiagnostics`, 1,784 `CachePlayback`, 1,466 `SourcePresentation`, 754 `SourceTiming` and 387 `Performance` entries—9,642 entries, or about 98.1% of that session. It also recorded 170 editor layout-transition events with Qt event type 76 (`QEvent::LayoutRequest`). This exposed substantial diagnostic and layout-transition work inside active render/editor paths.

A Point light at the authored 4096 shadow-map setting produced a 12288 × 8192 six-face atlas. An R32F color target alone is approximately 384 MiB per light before depth/stencil and compositor overhead.

## Hotspots corrected

1. **Logger configuration and I/O** — every eligibility check previously queried persistent settings, and every emitted line opened and closed the session file. Logging macros for Info/Warning/Error also constructed their complete payload before eligibility was known.
2. **Per-frame diagnostic snapshots** — source and canvas presentation copied a mutex-protected GPU-session diagnostic structure even when the associated log categories were disabled.
3. **Editor layout churn** — routine `QEvent::LayoutRequest` events generated by playback UI updates were treated as structural layout transitions, repeatedly stopping normal GUI refresh pacing.
4. **Point-shadow allocation** — the shared shadow-map preference was interpreted as the resolution of every Point-light cube face, making the complete 3 × 2 atlas six times the authored planar pixel count.

## Implemented changes

- Cached logger enable/level/mirroring/category state in atomics and refresh it only after a logging preference changes.
- Added lazy eligibility guards to every BGL logging macro.
- Kept one append-mode session file open and buffered writes to 64 KiB or 250 ms; warnings/errors flush immediately.
- Disabled SourceTiming, SourcePresentation and RenderDiagnostics by default. They remain available as opt-in diagnostics.
- Guarded source/canvas diagnostic snapshots behind category checks.
- Removed `LayoutRequest` from editor structural-transition detection.
- Kept Spot/Parallel shadow maps at the authored resolution and used half-resolution faces for Point-light atlases. This reduces Point atlas area from 6R² to 1.5R² (4× lower) at the same preference.

## Expected impact

- Greatly lower CPU allocation/formatting and registry/settings traffic when verbose diagnostics are disabled.
- Far fewer synchronous filesystem operations during playback and interaction.
- Removal of an avoidable render-session mutex read from normal source/canvas presentation.
- More stable editor playback while labels, panels and transport controls update.
- Point-shadow color-target memory reduced from about 384 MiB to 96 MiB per light at the 4096 setting, and from about 96 MiB to 24 MiB at the 2048 default, before depth/stencil and driver overhead.

## Validation boundary

The source contracts and package metadata are validated in this delivery. Final frame-time, GPU-memory and OBS responsiveness measurements require the native Windows OBS/Qt/D3D11 environment and representative production titles.
